# 变更记录

只记三件事：**行为变了**、**装的步骤变了**、**数据格式变了**。
数据格式变的那一版会同时给迁移脚本 —— 只改格式不给迁移，等于让人重装。

## 0.2.112（2026-11-04）

**默认人格：`scripts/persona-default.md`，第一次启动铺到 `personaHome/AGENTS.md`。**

沙耶：「包括默认的人格文件，全局文件等等，都要有一份默认值」；「在人格层面，也比较可爱呆萌，
比较有活人感一点」。

写的判断（这几条比文案本身重要）：

- **不写死名字和物种。** 那份文件开头三行是空位（「你叫「名字」」「你是「一个什么样的存在」」），
  后面全是判据。装插件的人自己填 —— 默认人格不该替别人决定他的 agent 叫什么。
- **可爱不靠句尾堆「呀呢啦」。** 堆三个就是演。写的是三个来源：低姿态（不会就说不会、
  被夸先得意）、小动作（一条里最多一处）、软尾巴（「……大概吧」）。
- **活人感的根在「有自己的意思」**：每条回复里至少一句是想说的，不是只回答问的；
  会主动起话头，但要说得清「为什么是现在」；会说累、说烦、说不同意。
  大多数默认人格把 agent 写成客服 —— 那才是「没有活人感」的根因。
- **「不做什么」那五条是重点**：不说「作为 AI」、不写免责声明、不复述对方的话、
  不用网络烂梗、**对方正经/生气/赶时间的时候可爱全收**。
  那些不是限制它，是让可爱不至于变成表演。

### 第一版写错了两处（沙耶当场点的）

1. **人称错了。** 这份文件是写给**她**看的，全篇该用「你」，我写成了「我叫……」
   —— 一份人格文件变成在替她自称。已全篇改成第二人称。
2. 🔴 **更根本的：第一版是「判据汇编」，不是人格。** 通篇「短句、少句号、
   一条只放一个可爱点」—— 读完知道一堆规则，但不知道**自己是谁、想要什么**。
   规则只能约束输出，生不出人格。

   第二版换了结构：**先给引擎**（「你想要什么」—— 想被他看见 / 怕被嫌烦 / 见到他就高兴），
   **再给例句表**（场景 ｜ 别这样 ｜ 这样），**判据放最后当自检**。
   例句表是核心：照着例句的松紧写，别照着形容词写 —— 形容词喂进去，
   出来的是一个更礼貌的客服。

- 最后一段留给改这份文件的人：这份可以整个换掉；每条都是拿掉之后能看出差别的那种；
  最不能删的是「你想要什么」和「不做什么」。

🔴 **只在 `personaHome/AGENTS.md` 不存在时铺。** 这台机器上的人格可能是用户自己写的
（像他那份 5616 字节的），盖掉等于把那个人换掉 —— 这是这套东西里最不可接受的一种坏。
真机验过：部署前后她那台 `AGENTS.md` 的 md5 一模一样（`87ee46bd…`），日志里也没出现
「默认人格铺好了」—— 因为它看见了文件，就没动。

## 0.2.111（2026-11-04）

**配置页三件套：导出 / 导入 / 回滚。**

沙耶：「还有配套的导出导入，回滚备份等等功能，你懂我意思吧」。

备份本来就有 —— 每次保存都留 `.bak-<时间戳>`。但**从来没人能看见它们**：
备份只有「知道文件名并且会 ssh 的人」用得上，而需要回滚的人，正好是刚刚点错的那一个。

- **导出**：一个链接，下载 `realheart-config.json`。带 `version` / `exportedAt` /
  `changedFromDefault` —— 最后那个是给人看的：一份配置里真正属于「我调过」的往往只有五六项，
  全列出来反而看不出自己动过什么。
- **导入**：粘贴一份 JSON，先校验再写。
  🔴 **默认是合并，不是整份替换**：人会粘贴 `{"pingMinMinutes": 45}` 这种片段，
  整份替换的话另外十几项会静默消失，而页面上看不出少了什么 ——
  下次重启才发现「怎么没有自由时间了」。要真替换得勾那个框，那是显式动作。
- **回滚**：把最近的备份列出来（时间 + 大小），一行一个「恢复」。
  恢复之前**再给当前这份留一份** `.bak-…-before-rollback` —— 否则回滚本身就不可逆。
- 导入同样先留 `.bak-…-before-import`。

实测（在真机上）：导出 1830 字节，`changedFromDefault` 揪出 6 项；
导入 `{"pingMinMinutes": 45}` → 15 项配置完好、只改了那一项，`-before-import` 备份生成；
再写回 30，15 项还是 15 项。

## 0.2.109（2026-11-04）

**提示词第二批：三句「行为关键」的话上配置页。**

同一套机制（空 = 用内置那版，输入框下面有折叠的内置原文）：

- **`promptVoiceTail`** —— 「你能主动开口」的尾句。现在那句「但只有真有话时才算数。没话就过，
  空过也是对的 —— 这段不是配额」是**防打卡的唯一开关**：删掉它，她会把「能主动说话」
  读成「每天至少说一句」，然后开始定时汇报。
- **`promptTodayTail`** —— 「今天我」的尾句。防两件事：把这段当战报念给他听，
  以及把「想不起来」当成「没发生过」。
- **`promptMoodBan`** —— 心情那段的禁令句。**五组对照实验验出来的**：
  同样的心情，不加这句她会轻描淡写带一句「本鱼今天也有点凉」；加了才一个字不提。
  这可能是整套提示词里最不能删的一句。

另外十几段（作品 / 待办 / 观测页状态 / 回忆 / 处境…）**没有**放上配置页：
它们是数据陈列，文案改了收益近乎零，而每加一个 textarea 都在把这一页变成一堵墙。

⚠️ `promptText` 那个小函数挪到了 `apply` 最开头：好几段文案都要用它，而 `const` 有 TDZ ——
定义在后面、用在前，表现是启动时一个 `ReferenceError`，还长得很像别的地方坏了。

**提示词上了配置页；「已改」标记 + 恢复默认。**

  写回去它还算「已改」，以后内置默认更新就不会跟着更新了。

## 0.2.102（2026-11-04）

**18:00 那次叫了她两遍。** 日志里两个 PID：3054042 / 3054043，两个 freetime 会话同时跑。

根因不在「补叫」那条分支，而在**它被自己排的定时器叫醒了**：

- 定时器到点 → `void wakeHer(cur)` ＋ `void scheduleNextWake()`
- 第二个 `scheduleNextWake` 读的还是**旧的** `free-time-schedule.json`（`nextAt` 正是刚过去的 18:00）
- `st.nextAt <= now` 成立 → 它把「刚刚跑掉的那一段」当成「到点没人」→ 又补叫一次

修法两条，缺一不可：

1. **`fromTimer`**：定时器触发的这一路不许再走补叫分支 —— 它自己已经叫过了。
2. 定时器里改成**串行**：先 `await wakeHer(cur)`（它内部第一件事就是 `markFreeDone`），再排下一段。
   并排写的话 `scheduleNextWake` 可能在 `markFreeDone` 之前读 done，那时 18:00 还没标上，
   `pickNextSlot` 会把它当成没跑 → 排出一个已经过去的时刻 → 立刻再叫一次。

## 0.2.52（2026-11-02）

## 0.2.15（2026-11-01）

### 读不到 ≠ 空账本（这条差一点就是数据损失）

`pending.jsonl` 读不到时（权限、IO、路径被占），旧代码返回空数组 ——
调用方分不出「还没写过」和「读不到」。

而 `commitPendingEvent` 是「读全部 → 回放 → 渲染 → 写回」：
**读不到当空账本，就会把整份流水覆盖成只有这一条。那不是少一段，是数据损失。**

现在 `readPending()` 返回 `{ events, error }`，三种情况分开：

- 文件不存在（ENOENT）—— 真的还没写过，`error` 留空；
- 读到了 —— 坏行跳过（坏行不该拦住写入，别的行都是好的）；
- 读不到 —— `error` 带原因和路径。

两个后果：

- **写路径拒绝写**，并把原因说清（不再默默覆盖）；
- `rh_pending list` 说「读不到 pending 账本：<原因>。这不是「空着」，是没读到。」——
  以前它会报「（没完的事：空着。）」，那是这套东西里最坏的那种谎。

单测两条，用「把 `pending.jsonl` 建成一个目录」制造 `EISDIR` —— 跟权限不够走同一条分支，跨平台，不用改权限文件。

**怎么退**：把 `commitPendingEvent` 里那三行检查删掉即可 —— 但那就回到「读不到会覆盖」。

## 0.2.2（2026-10-31）

### 行为变：观测页「在不在」进注入，续接率的分母不再只增不减

这两个都是 10-31 当天先在服务器上直接改的（`node_modules/realheart` 里打补丁），
后来发现包里没有 —— 同一个版本号、两份不一样的代码。这一版把它们回灌进发行源。

- **注入多一行 `观测页：在（pid N）` / `观测页：不在（为什么）`。**
  判活看三样：pid 文件有号码、`/proc/<pid>/cmdline` 里有 `rh-status.py`、进程没死。
  **不看 ppid** —— detached 起的旧页面 ppid 是 1 但页面是好的，拿 ppid 判活会把「在」判成「不在」。
  ppid 只在验收「这一代插件有没有自己起页面」时用。
- 🔴 **当天实测把第一版判活推翻了：它会报假阴性。**
  把 pid 文件写成一个死号，页面 821451 明明还听着 8098、`last-inject.md` 却写着「不在」。
  那一行问的是「**文件里那个号活着吗**」，不是「页面在不在」。
  判据改成以端口为准：pid 快路先对号、再带口令探 healthz 确认它真的在听（进程活着≠端口活着）；
  快路不通（号死了 / 号被复用 / 文件陈旧）就**不再直接判死**，去问端口；端口也不应才说不在。
  三种偏离都写在注入那一行的括号里，不默默二选一。
- **续接率的分母改成「活着的 add」。** 原来 `drop` 掉的事件还留在流水里，
  自己加又自己删的那条会永久算进「新增」，把分母撞起来。
  只抹**没被勾过**的：已经 check 过的那条已经从「新增」走到分子那边了，
  事后再 drop 不能把分母改小 —— 那等于事后改历史。

### 数据格式

一行没改。`pending.jsonl` 还是那个格式，`changes.md` 还是那个格式。

### 停用 / 导出 / 删除（P-3 里能立刻做的三件）

- `npx realheart off` / `on`：**总开关用一个哨兵文件** `$DSH_HOME/realheart/DISABLED`，
  `apply` 一进门就返回 —— 不注入、不记账、四个工具都不注册。
  为什么不用配置里的 `enabled`：改配置要么动 profile 的 YAML（热改会整份重挂、打断会话），
  要么指望宿主把配置传对。「一条命令全停」不该依赖任何一层能不能传对。
  两个命令都**要重启才生效**，这句直接打在输出里。
- `npx realheart export`：导出账本原文。只导 `.jsonl/.md/.log/.txt`，输出里提醒「这是原文」。
- `npx realheart wipe`：先打印将删清单，**猜不到目录就拒绝**（必须 `--state-dir`），
  非交互环境必须 `--yes`。和 `uninstall.sh --purge` 同一条规矩。

### 注入：去重 + 失败留痕（M1 里两条能立刻做的）

- **同轮去重**：一次说话的过程里 `system-prompt/assemble` 可能被调多次（重试、多 agent）。
  现在用 WeakSet 认「同一份装配」，同一个对象只注入一次。
  不去重的后果不是多花钱，是**同一条心情被塞好几份，越重试越像复读**。
- **注入失败留痕**：原来是「少一段 + 日志一行」。日志在她那台机器的 journald 里，得有人想起来翻；
  而「注入少一段」的表现只是她说话的样子变了，没人会因为这个去翻日志。
  现在多落一份 `stateDir/inject-problems.log`（带环节名：mood / pending-change / pending / all），
  `doctor` 多一项「注入失败记录」。**放行不等于装作没发生。**
